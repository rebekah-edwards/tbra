# iOS release: what breaks, and how not to break it

Every item here is a defect that shipped or nearly shipped. They share one
cause, so read that first.

## The root cause: `project.pbxproj` is not a place to keep settings

`native-ios/project.pbxproj` is **gitignored AND regenerated by `xcodegen
generate`.** Any build setting configured there — by hand, or by Xcode's UI —
survives exactly until the next `xcodegen generate`, then silently reverts.

Nothing warns you. The project still builds. The app still installs on a
phone. The damage only shows up in a TestFlight upload, or in App Store
Connect, or in a tester's hands.

**Rule: if a setting must ship, it goes in `native-ios/project.yml`.**

A second, subtler trap in the same family: `INFOPLIST_KEY_*` build settings
(e.g. `INFOPLIST_KEY_UISupportedInterfaceOrientations`) are only consulted
when `GENERATE_INFOPLIST_FILE=YES`. This project sets it to `NO`, so those
settings are silently ignored — the key must be a real entry under
`info.properties` in `project.yml`.

## Run the preflight. Every time.

```bash
./native-ios/preflight-archive.sh <path-to.xcarchive> <expected-build-number>
```

It exits non-zero and refuses the upload on any of the failures below. Do not
upload an archive that hasn't passed it.

## The specific failures it guards

| What broke | How it looked | Why |
|---|---|---|
| **App icon missing** | App shipped with no `CFBundleIcons`; blank icon on the home screen | `Assets.xcassets` wasn't in `project.yml`'s `sources`, so `actool` never ran. Masked for a while by stale PNGs in DerivedData — a *clean* build would have caught it. |
| **Cleartext networking in Release** | `NSAllowsArbitraryLoads` in the shipping plist | The Debug/Release ATS split lived in `pbxproj`. Fixed by generating a clean `Info.plist` and pointing only the Debug config at `Info-Debug.plist`. |
| **Build number bump did nothing** | Uploaded as build 1 no matter what | xcodegen hardcodes `CFBundleVersion` to `1` unless you set it to `$(CURRENT_PROJECT_VERSION)` in `info.properties`. |
| **Build held for export compliance** | Never reaches testers | `ITSAppUsesNonExemptEncryption` missing from the plist. |
| **Upload rejected, error 90474** | "No orientations were specified" | `INFOPLIST_KEY_UISupportedInterfaceOrientations` ignored (see above), *and* `TARGETED_DEVICE_FAMILY` had drifted to `1,2`, which opts into iPad and then demands all four orientations. |
| **Extension version mismatch** | Upload validation rejects the bundle | The widget extension's `CFBundleVersion` must equal the app's. |
| **Debug endpoint in a shipping build** | App points at the Mac's tailnet IP | Archiving the Debug configuration. |

## Release procedure

1. Bump `CURRENT_PROJECT_VERSION` in **`project.yml`** (never `pbxproj`).
2. `xcodegen generate`, then regenerate `Info-Debug.plist` from the fresh
   `Info.plist` plus the ATS key — generation overwrites it.
3. Archive with **stable Xcode** (`/Applications/Xcode.app`). Beta Xcode
   uploads are rejected: "Unsupported SDK or Xcode version".
4. **Run `preflight-archive.sh`.** Stop if it fails.
5. Export to an `.ipa` (`destination: export`, not `upload`) so there's an
   artifact to validate and re-upload without rebuilding.
6. `xcrun altool --validate-app` — catches Apple-side rejections *before* the
   upload rather than by email afterwards.
7. `xcrun altool --upload-app`.

## Reading App Store Connect afterwards

- **A build in `PROCESSING` does not appear in the ASC API's `/v1/builds`
  at all**, and shows no icon in the web UI. Absence there is not evidence the
  upload failed. Apple states processing can take up to 24 hours.
- `xcodebuild -exportArchive` with `destination: upload` prints "Upload
  succeeded" without confirming delivery. `altool --upload-app` returns a
  Delivery UUID, which is stronger evidence.
- Apple's notification email goes to the **Account Holder**
  (`rebekah@clara.agency`), not to any address used for testing.
